# 🎛️ Training Ground (бывший Wave & Level Visual Editor)

Визуальный интерактивный веб-редактор боевых волн, таймингов и кривых сложности для игры **Codex Tactics**.

---

## 🚀 Быстрый запуск

### Вариант 1 (В один клик из корня проекта):
Запустите файл:
```bat
Scripts/run_wave_editor.bat
```

### Вариант 2 (Через терминал):
```bash
cd Tools/WaveEditor
npm run dev
```
Редактор автоматически откроется в браузере по адресу: **http://localhost:5173**

## 🏟️ Отделы Training Ground (с 2026-10-25)

Вверху страницы — переключатель отделов:

* **Волны** — редактор волн, оружия и скрытности (всё, что описано ниже).
* **Перемещение** — построения и сектора взгляда отряда (`docs/design/FORMATION_SECTORS.md`, договор
  `docs/design/FORMATION_CONTRACT.md`): прогон отряда по маршруту раскладки в симуляторе прямо в браузере (0 токенов,
  без Unreal), проверки прогона, бот и обучение (тюнер).
* **Левел-дизайн** — аудит раскладок `Content/Data/FormationLab/*.json` (схема, точки маршрута в стенах, недостижимые участки,
  зоны без маршрутов, зоны, где классификатор не успевает переключиться).
* **Боевая лаборатория** (с 2026-11-01, `docs/design/COMBAT_LAB.md` раздел 7) — работает по картам:
  * **Выбор карты** (в шапке отдела, запоминается в браузере): `L_FormationLabCombat` (по умолчанию; без параметра `map` API ведёт себя
    как раньше) и каждая **сгенерированная** карта `Content/Maps/Generated/<имя>.umap`, у которой есть `Content/Data/LevelJson/<имя>.json`
    с блоком `bot_route` (например `L_Gen_Depot_1`; без `bot_route` карта в списке не появляется). Всё ниже — настройки, маршрут, карта,
    серии и отчёты — относится к выбранной карте: `GET /api/combat-lab/maps` отдаёт список, остальные запросы принимают `?map=<id>` (GET)
    или `map` в теле (POST); неизвестный id → 400. Превью сгенерированной карты строится из принятой раскладки
    (`levelgen_layout` уровня, `Content/Data/LevelGen/accepted/*.json`): стены, прямоугольники зданий, лестницы, точка старта.
    Чистая логика — `src/combatLab/maps.ts` (тесты `maps.test.ts`).
  * **Настройки уровня** — блоки `pressure` / `cheats` файла уровня выбранной карты (`Content/Data/LevelJson/<карта>.json`; копия — в `Saved/TrainingGround/combat_lab/backups/<карта>_<время>.json`): расписание групп,
    размеры групп и лимиты живых, доли патрулей / засад / скоординированных засад, веса пяти типов врагов (громила и крио-дрон —
    никогда), конус взгляда, отступ засады от стены, перенос засад, задержка штурма после флангов, сид, бессмертие, бесконечные
    патроны. У каждого поля — значение по умолчанию и диапазон; проверка та же, что у парсера игры (`src/combatLab/pressureSettings.ts`
    ↔ `LevelJsonRules::ParsePressureSettings`, тест `CodexTactics.LevelJson.PressureFieldsGolden`). «Сохранить в уровень» пишет только
    изменённые значения, копия прежнего файла — в `Saved/TrainingGround/combat_lab/backups/`, страница показывает разницу.
    **Пресеты** (`Content/Data/CombatLab/presets.json`): Default, Patrols only, Ambush heavy, Coordinated only — один клик; свои — кнопкой
    «Сохранить как пресет». Файл пресетов **один на все карты**, а точки засад (`pressure.ambush.points`) — данные карты: пресет, применённый
    к другой карте, **не трогает её собственные точки**; пресет, сохранённый со сгенерированной карты, хранится **без** `ambush.points` (так он
    никогда не затрёт точки лаборатории), а подсветка «активного» пресета на не-лабораторных картах точки не сравнивает. Справа — карта с маршрутом бота (`bot_route` уровня) и точками засад.
  * **Прогоны ботов** (на выбранной карте: `-Map` — её путь, `level.json` серии — копия её файла уровня; `batch.json` получает `map` и
    `level` = id карты; список серий и отчёт показывают только серии этой карты, серии без `level` — старые, лабораторные) — N забегов × M минут (по умолчанию 4 × 10, по 2 одновременно) в Unreal без рендера: бот ведёт отряд строем по
    маршруту уровня (стены, углы, проёмы, четыре вышки), дерётся со встречными, заканчивает по времени; сид давления = сид + номер забега;
    играются текущие настройки страницы (даже несохранённые — копия уровня кладётся в папку серии). Пока идут — живой ход (точка
    маршрута, контакты, бой, построение каждого забега). После — отчёт по каждому забегу и итог: маршрут (пройден ли, насколько, где и
    почему застревал), контакты (патруль / засада / скоординированная, время до первого взгляда бойца, удары с неприкрытой стороны,
    построение в момент контакта), смены построений по типам, прижатия к стене, смены стоек (всего, в минуту, по бойцам), урон
    (с бессмертием — поглощённый), патроны (с бесконечными — сколько было бы потрачено), подъёмы по лестницам, нокдауны, карта с местами
    застреваний и контактов и сводка Jev в 3 строки. Для сгенерированных карт запись забега может нести необязательный массив
    `route.drops` — спуски через проломы крыши / пола (`{ waypoint, label, via, fell, scripted, seconds }`: `fell` — лидер упал через
    ссылку спуска, `scripted` — спуск не удался и бот перенёс отряд): в отчёте — итог (всего / упали сами / перенесены скриптом), список и
    колонка по забегам, строка в `report.md`; старые записи без поля читаются как «нет спусков». Файлы серии: `Saved/Telemetry/combat_lab/<серия>/` (`runs.jsonl`, `report.md`,
    `aggregate.json`, `jev.txt`, `Bot-<n>.log`).
  * **Редактор карты** и **Симулятор** — следующий этап (вкладки зарезервированы).
* **Генератор уровней** (`docs/design/levelgen/LEVEL_GENERATOR.md`) — по эталону дизайнера (`Content/Data/LevelGen/refs/*.json`,
  прочтение его карты в `docs/design/levelgen/REF_*.md`), seed и параметрам (размер, плотность укрытий, варианты маршрута,
  вертикальность) генератор делает оригинальные серые раскладки с уровнями высоты по 3 м (−1 канал, 0 земля, +1, +2 крыши),
  симулятор проверяет обязательный маршрут (он должен быть проходим), механики, обзор, засады и сходство с эталоном; критики —
  Jev (типизированные суждения, бесплатно) и Claude API (видит обе картинки, лимит в долларах); принятые раскладки —
  `Content/Data/LevelGen/accepted/` для сборки карты в UE (`Scripts/Editor/build_levelgen_map.py`).

Командная строка (`Tools/TrainingGround`):

| Команда | Что делает |
|---|---|
| `npm run bot:movement -- --layout sample_small --members 2,3,4 --seeds 4` | серия прогонов → `Saved/TrainingGround/movement/report.md` (≤ 30 строк) и `runs.jsonl` |
| `npm run train -- --budget-usd 5 --rounds 10 --client claude` | обучение: модель предлагает параметры `formation_config.json`, симулятор их оценивает; `--dry-run` — без вызова API; `--client mock` — без сети |
| `npm run redteam -- --budget-usd 5 --rounds 4 --client claude` | «красная команда»: модель придумывает раскладки, ломающие правила строя; бот их проходит (auto + все ручные формации), упавшие сохраняются в `Content/Data/FormationLab/redteam/` как регрессия (`expected_fail`) → `redteam_report.md`; `bot:movement -- --layouts redteam` — прогон регрессии |
| `npm run golden` (`-- --check`) | эталонные векторы для C++ parity-тестов (`golden/formation_<Rule>.json`, `golden/combatlab_pressure_fields.json`) |
| `node src/combatLab/cli/report.ts --batch <папка серии>` | отчёт серии ботов боевой лаборатории заново (`report.md`, `aggregate.json`); серию запускает страница или `Scripts/bot_run.ps1 -Map /Game/Maps/L_FormationLabCombat -ReportDir <папка> -DurationSec 600 -Runs 4 -Parallel 2` |
| `npm run levelgen -- --seed 1 --seeds 3 [--size 177x124 --density 1 --variants 3 --verticality 3 --no-sim] [--accept <name>]` | генератор уровней: кандидаты + оценка → `Saved/TrainingGround/levelgen/<name>.json`, `.eval.json`, `report.md` (≤ 30 строк на кандидата); `--accept` копирует кандидата в `Content/Data/LevelGen/accepted/` |
| `npm run levelgen:critic -- --layout <name> --client claude\|jev\|mock --budget-usd 2 [--model claude-opus-5-5] [--dry-run]` | критик кандидата: Claude (картинки + метрики, расход в `critic_ledger.json`), Jev (типизированные суждения), эвристика |
| `npm test`, `npm run typecheck` | тесты логики и проверка типов |

Платные только вызовы модели в обучении: ключ берётся из окружения этого компьютера (`ANTHROPIC_API_KEY` / `TYPESAFE_API_KEY`)
и не печатается; расход ограничен `--budget-usd`. Агент читает только `report.md` / `train_report.md`.

## 🎮 Возможности редактора:

1. **Интерактивная кривая сложности (Difficulty & Threat Curve):**
   * Расчет в реальном времени: Суммарный DPS орды, общее HP волны, интегральный индекс угрозы.
   * Проекция шанса выживания (Winrate %) с учетом прокачки отряда по волнам.
   * Клик по любой волне на графике мгновенно открывает её параметры в инспекторе.

2. **Цветовая диаграмма состава орды (Enemy Composition):**
   * Наглядные доли каждого типа врагов в каждой волне:
     * 🐺 **Гончие** (Голубой)
     * 🏹 **Стрелки** (Фиолетовый)
     * ❄️ **Громилы** (Оранжевый)
     * 🧟 **Промёрзшие** (Серый)

3. **Глобальные слайдеры кривой баланса:**
   * Слайдер крутизны нарастания HP (до 2.5x в финале).
   * Слайдер нарастания урона монстров (до 2.2x в финале).
   * Количество волн на уровне (от 2 до 15 волн).
   * Время начальной подготовки и передышки между волнами.

4. **Быстрые пресеты баланса в 1 клик:**
   * ⚖️ **Стандарт** — классическая плавная прогрессия.
   * 🔥 **Экспонента** — хардкорный взрывной рост сложности.
   * 🐺 **Орда (Swarm)** — орды легких быстрых мобов.
   * ❄️ **Элита / Боссы** — меньше врагов, но много тяжелых громил.
   * ⚡ **Быстрый тест** — короткий забег на 2 волны для тестирования механик.

5. **Работа с JSON (Data Contract):**
   * Кнопка **«Сохранить в JSON»** экспортирует валидный файл `level_XX.json`, готовый для игры и автотестов.
   * Кнопка **«Загрузить JSON»** позволяет открыть любой файл уровня из папки `Content/Data/LevelJson/` (Unreal-репозиторий; игра читает их при старте уровня).

## 🕵️ Вкладка «Скрытность и бой»

* **Восприятие врагов** — зрение, угол обзора, заметность по стойкам, время обнаружения, слух по походке / выстрелу / гранате, нюх (только гончая), поиск после ловушки → `Content/Data/AI/enemy_perception.json`.
* **Орда — по умолчанию** → `Content/Data/AI/horde.json`.
* **Уровень** (выбранный в шапке): начало боя `combat_start` (авто / засада / кнопка), время поиска патруля, орда вкл/выкл и переопределение орды → `Content/Data/LevelJson/<level_id>.json`.
* **Консольные переменные Codex.\*** — справка; ручки скрытности `Codex.Perception.*` / `Codex.Patrol.*` пишутся в `Content/Data/AI/ai_tuning.json` (`cvars`).

Сохраняются только изменённые значения: остальные ключи и оформление файлов не трогаются. Тесты логики: `npm test`.
