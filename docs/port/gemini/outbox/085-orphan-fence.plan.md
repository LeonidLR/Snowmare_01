# План 085: Устранение сиротского забора F_x1_8_t1003 и отображение заборов на плане

## 1. Диагноз и первопричина (Root Cause)
1. **Почему уцелел забор `F_x1_8_t1003` при перегенерации X6:**
   - В процедуре `applyTemplates` (`Tools/TrainingGround/src/levelgen/regionRegen.ts`) отсечение старых объектов заменяемого блока выполняется через `inBlock(g.centre)`.
   - Для семейства забора `F_x1_8_t1003` (6 сегментов внешнего забора макро-квартала `x1_8`) центр `g.centre` рассчитывается как середина bounding box всех вершин: `[9640.57, 16624.16]`.
   - В режиме `full` квартал `x1_8` был нарезан на новые парцелы (`LOT_x1_8_4_1_1`, `LOT_x1_8_5_1_1` и др.) с внутренними проездами/переулками между ними. Точка `[9640.57, 16624.16]` попала ровно в межблочный зазор (проезд Y=16461..16672), где `lotAt(lots, p)` возвращает `undefined`.
   - В результате `applyTemplates` не удалил `F_x1_8_t1003`.
   - Затем в `mergeAttempt` оба объекта — внешний забор `F_x1_8_t1003` и новые внутренние заборы парцелов (`F_x1_8_4_1_1_t1003`, `F_x1_8_5_1_1_t1003`) — оказались в списке добавленных/сохраненных групп, так как проверка `overlapsAny` на полигонах с отступами `TOUCH_CM` не выполняет явного пересечения отрезков открытых линий.

2. **Почему забор не был заметен дизайнеру:**
   - В `LayoutView.tsx` заборы `kind === 'fence'` рисовались тонкой бледно-желтой линией (`#e6e678`, толщина 1 px), которая на масштабе карты X6 (430 м, масштаб ~0.012 px/см) визуально терялась на фоне заливок зон `zones` и дорог.

## 2. Предлагаемое решение

### A. Очистка внешних заборов при перегенерации / разбиении блоков (`regionRegen.ts`)
- **Выбранное правило:** Удаление объемлющего/устаревшего семейства забора (Remove enclosing/crossing parent fence family).
  - *Обоснование:* При перегенерации квартала дизайнер заменяет внутреннюю структуру новыми объектами. Оставлять внешний забор родительского блока, который пересекает новые улицы и здания, категорически некорректно. Сброс свежих групп (`overlaps_kept`) вместо этого заблокировал бы генерацию новых участков.
- **Реализация:**
  1. В `applyTemplates`: группа забора `g` считается принадлежащей блоку не только по точечному центру `g.centre`, но и если id семейства забора содержит префикс родительского блока (`F_<parent>_...`) либо если сегменты забора пересекают/охватывают геометрию заменяемых участков.
  2. В `mergeAttempt`: добавить явную проверку пересечения отрезков (`segmentsIntersect`) между свежими группами и сохраненными заборами. Если сохраненный забор пересекает новые стены/здания перегенерированного блока — такое семейство забора исключается.

### B. Финальный валидатор пересечений стен и UI-предупреждения
- Создать валидатор `validateWallCrossings(layout: GenLayout)`:
  - Проверяет попарное пересечение отрезков всех стен разных семейств (`segmentsIntersect`).
  - Проверяет пересечение сегментов стен с полигонами отпечатков зданий (с учетом поворота зданий `footprintPoly`).
  - Возвращает список конфликтов с координатами точек пересечения.
- **Отображение в UI (`LayoutView.tsx` / `LevelGenDepartment.tsx`):**
  - Отрисовка контрастных красных маркеров/перекрестий в точках конфликтов.
  - Кнопка «Принять» выводит предупреждение о наличии пересечений стен.
  - Добавление опционального действия "Удалить конфликтующие заборы" / "Удалить сиротский забор", позволяющего очистить сиротский забор прямо в UI.

### C. Четкая отрисовка заборов на слое земли
- В `LayoutView.tsx` и `PropsCanvas.tsx`:
  - Обеспечить четкую, контрастную отрисовку заборов (`kind === 'fence'`) на виде земли (`floorMode === 'ground'` или `layer === 'all'/'ground'`) — заметный цвет, контрастирующий с фоном и зонами (например, `#fbbf24` / `#fde047`), минимальная экранная толщина линии не менее 1.5-2 px.

### D. Инструкция по исправлению X6 без ручной правки JSON
- Файл `gen_ref_01_02_depot_1_x6.json` вручную НЕ редактируется (строго по правилам).
- В отчете будет описано, как дизайнер исправляет X6:
  - Вариант 1: В веб-интерфейсе при открытом X6 нажать кнопку очистки конфликтующих заборов валидатора и «Принять».
  - Вариант 2: Выделить рамкой зону квартала `x1_8` и нажать перегенерацию с исправленным кодом, после чего нажать «Принять».
