### Задача 06: Python Regex парсер (`06-regex.md`)
- **Промпт:** `"Give a Python regex that matches lines like '[2026.11.11-13.05.07:103][614]LogStreaming: Display: FlushAsyncLoading(608): 3 QueuedPackages' and captures the timestamp, frame number and the queued package count. Show it with a 5-line usage example."`
- **Результат модели:**
  - Паттерн: `r'\[(\d{4}\.\d{2}\.\d{2}-\d{2}\.\d{2}\.\d{2}:\d+)\]\[(\d+)\]LogStreaming: Display: FlushAsyncLoading\((\d+)\): (\d+) QueuedPackages'`
  - Скрипт использования и объяснение (всего 35 строк).
- **Анализ:**
  - Регулярка рабочая, но вместо 3 групп захвата содержит 4: введена ненужная группа `(\d+)` вокруг ID пакета `608`. В коде скрипта модель вынуждена брать `group(4)` вместо `group(3)`. Следовало использовать `FlushAsyncLoading\(\d+\): (\d+)` без скобок захвата на ID.
  - Нарушено требование `"5-line usage example"`: модель выдала 35 строк с вводным вежливым текстом ("Certainly! ...") и разделом объяснений.
- **Вердикт:** **PARTLY**.

### Задача 07: C++ генерация тестов (`07-test-boilerplate.md`)
- **Промпт:** `"Following the style of this test file, write ONE more test case: when 'scan' is false the look stays constant over time. Only the new test code."`
- **Входной файл:** `Source/CodexTacticsTests/Private/Formation/FormationSectorRulesTest.cpp`.
- **Результат модели:**
  Сгенерирован макрос `FORMATION_SECTOR_TEST(FFormationSectorNoScanTest, "NoScanConstantLook")`, цикл по времени и вызовы `FMath::IsNearlyEqual`.
- **Анализ дефектов:**
  1. **Ошибка компиляции C++:**
     `const FFormationConfig Config;`
     `Config.ScanAmpLead = 0.f;` — попытка записи в `const`-объект приведёт к ошибке компилятора MSVC `error C3892: 'Config': you cannot assign to a variable that is const`.
  2. **Смысловой провал архитектурного контекста:**
     Модель не знала, как устроена фича `scan=false` (которая передаётся параметром `bScan` в правила расчета), и попыталась "захакать" отключение сканирования через `ScanAmpLead = 0.f`.
     Но `ScanAmpLead` обнуляет амплитуду только командира (`Commander`). Роли `Right` и `Left` качаются по амплитуде `ScanAmpSide`, а задний дозор `Rear` качается между `PairScanFrom` и `PairScanTo`.
     В результате роли P, L и Z продолжали бы качаться, и проверки `bPConstant &= ...` провалились бы во время выполнения теста!
- **Вердикт:** **PARTLY / WRONG LOGIC** (Шаблон красивый, но код не скомпилируется, а если убрать const — провалится логически).

## 3. Итоговый вердикт: Категории задач для локальной модели

Модель `qwen2.5-coder:14b` демонстрирует высокую скорость и достаточный уровень понимания, однако имеет выраженные сильные и слабые стороны.

### ✅ Что МОЖНО передавать локальной модели (Level-1 задачи):
1. **Генерация Commit Messages по Git Diff:**
   - Модель превосходно извлекает суть изменений и строго соблюдает структуру Conventional Commits.
2. **Объяснение локального кода и функций (Code Explanation):**
   - Точно понимает математику, алгоритмы и локальные сигнатуры C++/Python/TypeScript. Идеально для комментирования и генерации документации на уровне функций.
3. **Первичный черновой драфт тестов (Boilerplate / Scaffolding):**
   - Отлично схватывает соглашения об именовании, тестовые фреймворки и макросы проекта (но требует обязательной валидации человеком или компилятором).
4. **Саммари больших отчётов без жестких лимитов по форматированию:**
   - Высокая точность извлечения ключевых фактов и цифр (98 вызовов, 13.9с и т.д.) без искажений.
5. **Диспетчеризация и форматирование сообщений чата (при наличии четкого шаблона).**

### ⚠️ Что ТРЕБУЕТ предосторожности (Ограниченное применение):
1. **Регулярные выражения и парсеры строк:**
   - Требуется автоматический прогон тестов — модель склонна создавать лишние группы захвата.
2. **Bash / PowerShell скрипты:**
   - Требуется явное указание флагов (`-Recurse`, глубины обхода, кодировок), иначе модель выбирает простейший одноуровневый вариант.
3. **Задачи со строгим ограничением длины/формата («ровно 5 строк», «only the command»):**
   - Модель часто игнорирует ограничения brevity и оборачивает ответы в Markdown/вежливые префиксы. Для скриптов требуется постобработка (regex strip).

### ❌ Что ЗАПРЕЩЕНО доверять локальной модели (Критичные риски):
1. **Реализацию логики C++ и системной архитектуры:**
   - Модель делает наивные предположения и локальные «хаки» вместо использования правильных проектных API/параметров (как в случае с `ScanAmpLead = 0` вместо `bScan`).
2. **Негативные проверки и глубокий статический аудит больших файлов:**
   - Склонна подтверждать «ALL OK» на беглом взгляде, если нет четкого машинного валидатора схемы.
3. **Финализацию кода без компиляционного гейта:**
   - Любой C++ код от локальной модели должен компилироваться и прогоняться через автоматические тесты до попадания в рабочий процесс.
