# Генератор уровней — слои карты и анализ узких мест / угроз (задача 074)

Ветка `feat/levelgen-layers` (от main 894eb481). Только TypeScript (Training Ground) + два новых конфига в `Content/Data/LevelGen/`
(`layers.json`, `chokepoints.json`). C++, `Content/Maps/**`, `.uasset`, `Config/*.ini` не тронуты. Принятые карты дизайнера и файл
пропсов `L_Gen_Depot_1.props.json` только читались: тесты пишут во временную папку, проверка страницы сверяет их байт в байт до и
после. Реальная сборка в Unreal не запускалась. Генерация пропсов не делалась (это задача 076) — слои только читают и правят формат.

Где: TG → «Генератор уровней» → «Генератор раскладок», новая панель **«Слои»** справа (над «Оценкой»).

## 1. Слои: как пользоваться

Карта разбита на слои; каждый объект раскладки и каждый предмет из файла пропсов карты принадлежит **ровно одному** слою
(проверено тестом на всех принятых картах, эталонной Depot, перегенерированной, повёрнутой и расширенной).

| Слой | Что в нём |
|---|---|
| 1 Дороги | только зоны улиц: `Z_ST_*` и зоны типа `street` |
| 2 Здания / структуры | здания, их стены, перегородки, парапеты, лестницы на крыши и этажи |
| 3 Мосты | мосты и пандусы через канал |
| 4 Преграды крупные · 5 средние · 6 мелкие | свободные стены, заборы, бордюры, все укрытия, ящики и бочки из пропсов — по правилу размера (п. 2) |
| 7 Мины · 8 Лут · 9 Особые предметы | из файла пропсов карты: мины; лут; турели, взрывные бочки и всё, что не мина / не лут / не простая преграда |
| 10 Цели | старт (S) и цели 1, 2, 3, 4 |
| Линия огня | прежние линии огня из окон и бойниц — теперь это слой (кнопка «Линии огня» над планом переключает его же) |
| Узкие места (засады / заторы) | новый анализ (п. 4) + четыре подслоя угроз (п. 5) |
| служебные (свёрнуты) | канал со стенами, кварталы-зоны, маршруты и точки врага, кромки перелаза — то, чего нет в списке дизайнера, но что рисует план |

В строке слоя: **галочка** — показать / скрыть; цвет; название; **число объектов**; **S** — «только этот слой» (ещё раз — вернуть все);
**карандаш** — сделать слой **активным**. Кнопки «все» / «ничего» вверху. «Цвета классов» — преграды на плане красятся цветом
своего класса (красный / оранжевый / жёлтый); выключить — прежние цвета. Подслои угроз сначала скрыты (на большой карте это сотни
значков) — включаются галочками.

**Состав слоёв — данные:** `Content/Data/LevelGen/layers.json` (id, название, цвет, правила `match` по типу объекта, виду, типу
квартала, варианту пропса, классу размера; шаблоны для «Добавить»). Инструмент откажется работать с конфигом, где объект попадает
в два слоя или ни в один. Старые карты грузятся без изменений (схема раскладки получила только необязательный блок `analysis`).

Ещё: кнопка **«скрыть эталон»** над планом — план занимает всю ширину (удобно на картах ×4 / ×6).

## 2. Правило классов преград (числа — `layers.json` → `size_classes`)

- **Мелкие:** высота ≤ **105 см** (классы перелаза 85 и 95 см + допуск: перепрыгивается с ходу, укрытие только пригнувшись).
- **Крупные:** высота ≥ **230 см** (закрывает обзор стоящему; 230 / 250 / 310 / 330 см, силосы) **или** площадь ≥ **20 м²** при
  высоте больше 105 см.
- **Средние:** всё между: высота 106–229 см и площадь < 20 м² (135 / 140 см: укрытие в рост, высокий перелаз).
- Высоты берутся из объекта (стена: `height`, длина × толщина; укрытие: `size`), для пропсов — из `props_balance.json`
  (`crate_s` 110 см и `crate_l` 140 см — средние, бочка 90 см — мелкая). `kind_class` позволяет принудительно назначить класс виду.
- На Depot ×4: мелкие — бочки 95, ящики 85, блоки 95, мешки 95; средние — остовы 140, котлы 140, заборы 135; крупные — силосы
  1200 и стены 330 (5 / 287 / 475 объектов).
- Проверено: во всех принятых картах нет высот между 161 и 229 см, поэтому граница «крупных» 230 см и вариант «закрывает обзор,
  от ~170 см» сейчас дают одно и то же разбиение; если появятся преграды 170–229 см, порог `large_min_height_cm` решит, куда они.

Правило написано мелким шрифтом под каждым из трёх слоёв в панели (числа подставляются из конфига).

## 3. Редактирование: инструменты действуют только на активный слой

Карандаш у слоя → блок «Активный слой» с инструментами. Объект другого слоя не выбирается и не меняется (проверено на странице:
на активном «мелкие» щелчок по остову ничего не выбирает, на «средние» — выбирает его).

| Слой | Что можно |
|---|---|
| Преграды (три класса) | выбрать щелчком, **перетащить**, повернуть на ±15°, **удалить** (кнопка или Delete), **добавить щелчком** из списка шаблонов класса; **«Перегенерировать слой в зоне»** — нарисуйте зону: внутри заново расставляются только укрытия этого слоя, всё остальное (стены, здания, укрытия других классов, маршруты) остаётся |
| Дороги | выбрать, удалить зону дороги (шаг отменяется «Отменить») |
| Здания | выбрать, удалить здание со стенами и лестницами (здание на маршруте или с целью — отказ с причиной); перегенерация — прежняя «Перегенерировать зону» («Полностью» / «Тип квартала») |
| Мосты, канал, кварталы | выбрать (посмотреть) |
| Мины, Лут, Особые | **поставить щелчком** (мина, растяжка; куча лута; турель, взрывная бочка), перетащить, удалить. Правки пишутся в `overrides` файла пропсов (формат PROPS_LAYERS.md: `add` с id `hand_<слой>_<n>`, `move`, `delete`) и сохраняются кнопкой **«Сохранить пропсы»** через существующий API (проверка ревизии, запрет на замороженный файл) |
| Цели | как раньше: «+ цель», перетаскивание, × |

Каждая правка раскладки — шаг «Отменить / Вернуть». Пока активен другой слой, старт и цели не двигаются. Без активного слоя план
ведёт себя как до слоёв. Если у карты нет файла пропсов (сейчас он есть только у `gen_ref_01_02_depot_1` → `L_Gen_Depot_1`), три
слоя пропсов пусты с пометкой «пропсы появятся после задачи 076».

## 4. Узкие места: что считается и по каким числам (`Content/Data/LevelGen/chokepoints.json`)

**Где ищем.** Свободное место земли — как его ходит симулятор отряда после вчерашнего исправления (стены + здания + все укрытия),
плюс канал вне мостов. Точки каждые 0,5 м вдоль: путей маршрутов по навигации, пути «старт → цели», осевых линий улиц (слой «Дороги»).
Внутри зданий не ищем (двери и комнаты — не уличные узкие места).

**Ширина прохода в точке** = расстояние до ближайшей преграды + расстояние до преграды напротив (лучи ±15°; точно, в сантиметрах).
Считается дважды: по «жёстким» преградам (стены, здания, крупные укрытия, край канала, борта моста, край карты) и по всем (с укрытиями).

| Вид | Правило | Числа |
|---|---|---|
| **узкий проход** | жёсткая ширина меньше порога | < **6 м**; полный балл при ≤ 2 м |
| **завал** | на 10 м улицы в полосе ±4 м не меньше 4 преград и под ними не меньше 12 % полосы; или свободный проход между преградами уже 2,5 м на 3 м и больше | полный балл: 10 преград / 35 % / проход 1 м |
| **каньон с высотами** | с обеих сторон объекты ≥ **230 см** не дальше **8 м** каждая, не меньше чем на 60 % длины участка | — |
| **единственный путь** | участок перекрывается (радиус 3 м), путь от точки за 12 м до него к точке через 12 м после ищется заново в рамке ±70 м: пути нет — «единственный путь»; есть — значение = удлинение / 40 м | вид «единственный путь» — когда обхода нет или он длиннее на ≥ 30 м |

**Оценка места 0…1** = min(1, сумма «вес × значение»): узко 0,25; завал 0,20; каньон 0,15; единственный путь 0,20; на маршруте 0,05
(основной 1, вариант / путь к целям 0,7, просто улица 0); спрыгивание 0,25; окна 0,10; снайпер 0,10; скрытый противник 0,10.
В список и в JSON идут места с оценкой ≥ 0,25, не больше 60. **Вид** места — первый подходящий из списка `kind_priority`
(единственный путь → засада сверху → каньон → завал → узкий проход → скрытый противник → огонь из окон → снайпер); остальные
признаки и угрозы перечислены в подсказке. Маршрут и улица под ним — одно место (не два).

**На плане:** контур участка, цвет по оценке (жёлтый → оранжевый → красный), кружок с номером. Наведение — подсказка: вид, оценка,
ширина, длина, причины с числами, какие угрозы. **Список справа** отсортирован по оценке; щелчок — план приближается к месту и
раскрываются причины. «Пересчитать», выбор погоды и времени суток (они меняют дальности обзора), сворачиваемый блок «Правила и числа».

## 5. Модель угроз: как атакуют враги (числа читаются из конфигов игры)

| Угроза | Как считается | Числа и откуда |
|---|---|---|
| **1. Засада сверху (спрыгивание)** | крыша, по которой можно ходить, или верх толстой стены, высотой в пределах «спрыгивающих» ссылок; точка улицы не дальше от края, чем вынос прыжка + удар. Крыша, куда ведёт только приставная лестница, считается вполовину (прыгуны по лестницам не лазят — их туда надо поставить) | высота **150–650 см**, вынос **250 см**, прыгуны — архетипы с `enemy_drops = 2`: **каттеры, гончие** — `Content/Data/Movement/falls.json` (`link.min_drop_cm`, `link.max_drop_cm`, `link.max_gap_cm`, `enemy_drops.*`) |
| **2. Огонь из окон** | окно или бойница здания, куда можно войти; точка в секторе ±75° от нормали окна, в дальности винтовки, с прямой видимостью (преграда закрывает, только если она выше линии «глаз в окне → цель») | m16: эффективная **28 м**, предельная **60 м**, спад точности до 0,1 — `Content/Data/Weapons/weapons_tuning.json` |
| **3. Снайпер на крыше** | крыша, куда человек может подняться (лестница, марш, люк); дальность = меньшее из дальности винтовки снайпера и его обзора с прибавкой за высоту; лучшие точки крыши (до 2) — те, что видят больше всего метров линий дальше его «предпочитаемого минимума» | винтовка снайпера **80 / 110 м**, предпочитает от **20 м** — `weapons_tuning.json`; обзор MARKSMAN 45 м × 2 (люди) × (1 + 0,25 за каждые 3 м высоты глаз, максимум ×2) × погода × время — `Content/Data/AI/enemy_perception.json` |
| **4. Скрытый противник** | место в ≤ 8 м ходьбы от линии, вплотную (≤ 1,5 м) к чему-то высотой ≥ 90 см, которое идущий отряд видит только вблизи: **дистанция раскрытия** = самая дальняя точка линии в окне 60 м с прямой видимостью «глаз стоящего → пригнувшийся противник» (для маршрута — только точки ДО места: отряд идёт от старта). Место засчитывается при раскрытии ≤ **12 м**. **Скрытность:** боец в режиме скрытности виден не дальше «обзор отряда × множитель»; где это сокращает раскрытие до ≤ 25 м — место «только для бойца в скрытности» (половинный балл) | обзор отряда **120 м** × погода × время — `enemy_perception.json`; множитель скрытности **0,4** — `Content/Data/AI/stealth_mode.json`. Ясный день: 48 м (скрытность новых мест не даёт); буран ночью: обзор 21 м, в скрытности 8,4 м |

**Значения по умолчанию (в конфигах игры этих чисел нет — заданы в `chokepoints.json`, ключи `*_default`, в панели помечены жёлтым):**
удар после приземления 150 см; верх стены годится от толщины 60 см; множитель «крыша только по лестнице» 0,5; сектор огня из окна
±75° (как у слоя «Линия огня»); высота цели 150 см (стоящий; в C++ `SightRules::ProfileHeight`); высота глаз 160 см
(`SightRules::EyeHeight`); профиль пригнувшегося 90 см. Остальные пороги (окно подхода 60 м, бросок 8 м и т. д.) — настройки анализа.

**Подслои на плане:** оранжевые стрелки «край → точка приземления»; голубые квадраты — окна, простреливающие места; пурпурные
ромбы — лучшие позиции на крышах с направлением взгляда; салатовые точки — укрытия с направлением на маршрут (пунктирные — только
для скрытности). У каждого значка подсказка с числами.

## 6. Что сохраняется в JSON карты («Принять» → блок `analysis`)

`analysis.version`, `geometry_hash` (если карта изменена после анализа — он считается устаревшим и пересчитывается), `conditions`,
`thresholds` и пять списков для игры / ИИ ЧВК / тренера:

- `chokepoints[]`: `id`, `kind`, `kind_name`, `tags`, `score`, `pos`, `line`, `poly`, `length_m`, `width_m`, `lane_m`, `route`, `sources`,
  `values` (вклад каждого признака), `numbers` (преград на 10 м, доля перекрытия, доля каньона, обе стороны с высотами, обход:
  `alternative` none / detour / n/a и `detour_m`, id точек спрыгивания, окон, крыш, укрытий, дистанции раскрытия), `reasons`.
- `dropAmbushSpots[]`: поверхность (`roof:<здание>` / `wall:<стена>`), `edge` (край), `land` (точка на улице), `drop_cm`, `gap_cm`,
  `access` (stairs / ladder / none / wall), `jumpers`, линия, места.
- `windowsCovering[]`: id окна, здание, этаж, позиция, направление, сколько метров линий простреливает, ближайшая дистанция, места.
- `overwatchRoofs[]`: здание, уровень, высота, дальность, доступ, `spots[]` (позиция, направление взгляда, покрыто метров, самый длинный луч), места.
- `hidingSpots[]`: `pos`, `facing_yaw` (к маршруту), `reveal_normal_m`, `reveal_stealth_m`, `stealth_only`, `blind` (за углом), `rush_m`,
  за чем прячется и его высота, `threatens` (линия, маршрут, точка), `place`.

Анализ детерминирован: та же карта + тот же конфиг → тот же JSON (тест, в т. ч. после записи / чтения JSON). C++ эти данные пока не читает.

## 8. Что проверить дизайнеру

1. Слои: скрыть / показать, «S», счётчики; хватает ли служебных слоёв (канал, кварталы, маршруты, кромки) или что-то перенести в основные.
2. Классы преград: согласны ли с границами 105 / 230 см и 20 м²; куда относить взрывные бочки (сейчас «Особые предметы») и ящики
   из пропсов (сейчас по размеру — средние).
3. Правка по слоям на Depot: перетащить / удалить / добавить преграду, «Перегенерировать слой в зоне»; поставить мину, лут, турель
   на `gen_ref_01_02_depot_1` и «Сохранить пропсы» (я не сохранял — файл ваш).
4. Узкие места на Depot ×4: верно ли названы первые 10; не шумит ли «снайпер на крыше» (с дальностью 110 м он есть почти у каждого
   места — это модификатор оценки); пороги 6 м, 4 преграды / 12 %, 8 м для каньона, 40 м для обхода.
5. Угрозы: числа по умолчанию из п. 5 (особенно удар после приземления 150 см и «крыша только по лестнице» ×0,5); порог раскрытия
   12 м; какие условия считать основными для сохранения (сейчас ясный день).

## 10. Не сделано / ограничения

- **Дороги:** нет «добавить / нарисовать дорогу» и нет перегенерации дорог — улицы это каркас карты, генератор их не пересобирает;
  удаление зоны дороги не убирает её из каркаса перегенерации зон.
- **Здания:** только выбор и удаление; перенос / поворот здания мышью не сделан; перегенерация «только здания» без укрытий не имеет
  смысла (укрытия ставятся вокруг зданий) — используется обычная перегенерация зоны.
- **Перегенерация по слою** — только укрытия трёх классов преград; заборы и стены (кольца шаблонов) ею не перекладываются.
- **Пропсы:** генерации нет (задача 076); добавленный вручную предмет на слое, которого нет в файле, создаёт пустой запертый слой
  этого вида — как игра (C++) читает такой слой, не проверено. Повёрнутые здания панель пропсов (вкладка T5) по-прежнему не знает.
- **Анализ — только земля:** этажи, крыши и дно канала как место отряда не анализируются; окна считаются по геометрии и дальности,
  без модели «кто из ЧВК реально займёт окно»; двери зданий как узкие места не считаются.
- **Спад точности** от эффективной к предельной дальности — приближение формулы игры (1 → пол 0,1, степень 2).
- **Условия:** анализ сохраняется для выбранных на странице погоды и времени (по умолчанию ясный день).
- На большой карте анализ пересчитывается после каждой правки ~1–2 с (страница на это время занята, список мест на это время
  пустеет); на время правок слой «Узкие места» и подслои угроз можно скрыть — тогда пересчёта нет, «Принять» посчитает сам.
- Колесо мыши в headless-проверке не эмулируется (CDP не возвращает подтверждение) — масштаб проверен кнопкой «+» и щелчком по
  списку; код колеса не менялся. Скриншоты сняты с dev-сервера этого worktree, где нет эталонной картинки (`Saved/MapRefs`) — на
  них она скрыта новой кнопкой «скрыть эталон».
- C++ не читает `analysis.*`; `HANDOFF.md` / `TASK_BOARD.md` не обновлялись (их ведёт оркестратор при слиянии).
