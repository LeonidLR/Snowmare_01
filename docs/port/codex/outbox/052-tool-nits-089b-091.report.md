## Диагноз

- При `rounds` с индексами `[2, 1]` запрос раунда 2 возвращал запись с индексом 1. Та же ошибка воспроизвелась с индексами `[1, 0]` в старом формате. Первый выстрел брался из порядка массива событий, даже если в конце массива встречался более ранний выстрел.
- `objective_capture.track.json` хранит `objective.radius=600` при `units=cm`. Прежний отчёт выводил `Radius 0.0 m` и назначал всем бойцам без лога фиктивный `Spawn ring`. Unreal пишет `objective.radius` в единицах трека (`Source/CodexTacticsDev/Private/Debug/PmcArenaCommand.cpp:2434,2445`), а в раундовом JSON использует `radius_m` (`:2589`).
- Проверка H3 уже использовала время экспозиции или `cover=0.00` из лога, но пропускала метку `/cover`. При её установке Unreal дописывает суффикс к состоянию бойца (`PmcArenaCommand.cpp:2205`).
- В `gate.py:104` ветка `except Exception: return rounds` обходила отклонение некорректной схемы адаптером. В воспроизведении `schema="broken"` и сырые значения `kills=1,2` прошли все три проверки.
