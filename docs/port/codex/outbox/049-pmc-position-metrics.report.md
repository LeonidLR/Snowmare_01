# 049 — позиционные метрики арены PMC, smart-enemies T‑04

## Handover

База `02adb288`, ветка `codex/049-pmc-position-metrics`. Для T‑04a добавлены пять наблюдений в `rounds[].defence` и три чистых unit-теста. Сборка и движковая проверка в процессе. T‑04b ждёт слияния T‑02 и T‑03. После слияния проверить три карты `L_Lab_Crossroads`, `L_Lab_Alley`, `L_Lab_Bridge` и запуск `PmcArena Opponent=Script Script=run`, затем реализовать сценарные проверки A-00A/B/C и воспроизвести ожидаемые FAIL.

## Диагноз и реализация

Старый трек давал плоские координаты, состояния приказа и события выстрела, а G008 снимал разнос защитников раз в секунду. Длительность контакта означала окна после выстрелов. Для T‑04a dev-арена теперь непосредственно наблюдает экипированную дальность, физическое движение, укрытие, доступные слоты и назначенные тактические посты. В результат попадают интервалы простоя для каждого бойца, доля защитников на позициях, угол при первом выстреле, самый длинный открытый пробег и разрыв между первыми выстрелами двух защитников.

Секторные посты G008 вне публичного снимка `CopyDefenceSnapshot`. Видимое занятие укрытия учитывается, а пост доступен только через `GetFighterPost`, который возвращает тактическое назначение. Для полного учёта G008 потребуется отдельное чтение приватного состояния команды с согласованным расширением разрешённых путей. Для открытого пробега поиск слота выполняется шестнадцатью направлениями от ног на уровне колена, затем использует штатный расчёт слота и navmesh. Это дискретное измерение с интервалом семплирования 0,2 с.
