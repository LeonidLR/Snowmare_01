## Click routing / regression risks
- No explicit vault click branch found in P/CodexTacticsPlayerControllerOrders.cpp: vault is automatically triggered later by path movement. Ladder click is explicit (:228-236), mapping hit ladder to opposite-end move target.
- P/CodexTacticsPlayerControllerOrders.cpp:462-471 handles wall cover/wrap before ordinary movement; :500+ handles interactable menus. Add mantle/top intent before generic cover/menu/ground-order consumption, preserving Alt/attack/tactical precedence rather than making every crate click climb.
- D = Source/CodexTacticsDev/Private/Debug/: ClickRulesSmokeCommand.cpp:123-126 requires barricade click menu; BarricadeVaultBackSmokeCommand.cpp:2-7 protects bidirectional traversal/nav after relocation. VaultSmoke/DepotVaultSmoke, FallDropSmoke and DropLinkReachSmoke are existing regression candidates, not mantle coverage. None run here.
- MANTLING.md:48-53 overlaps step/vault/mantle bands and describes custom movement modes absent from the inspected implementations. Agree deterministic precedence for thin barrier vs deep platform; preserve existing vault and ladder thresholds.
- Add explicit top nav island generation, per-slot collision/headroom sweeps, moving/destroyed-geometry aborts, stance/weapon ownership and path resume. A collision-disabled arc alone is unsafe for tall/deep geometry or occupied landings.
- Open questions: which generic climb assets can be retargeted/warped at 1/1.5/2 m, how much height scaling is acceptable, and should click-on-top or modifier request mantle? Binary asset/root motion/clip duration and active retarget compatibility were intentionally not verified.
