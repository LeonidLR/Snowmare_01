## 2. Environment facts and traps (read before touching anything)

| Fact | Consequence |
|---|---|
| Engine `C:/Program Files/Epic Games/UE_5.8`, project `Documents/Unreal Projects/CodexTactics` | Scripts assume these paths. |
| **`Documents/Codex/unreal` is a junction to this repo** | Another agent working "in Codex/unreal" works on the *same files*. Builds / tests collide (DLL locks, overwritten `Saved/Logs`). Claim work in TANDEM and build one at a time. |
| The open **Unreal Editor locks the module DLLs** | Close it before `build.ps1` (graceful: `CloseMainWindow`, wait 45 s; never force-kill a window with a save dialog). The user allowed closing / reopening it. |
| Build log `Saved/Logs/Build.log` is UTF-16-ish | Read it with PowerShell `Get-Content`, not grep. |
| UHT forbids names shadowing `AActor` members (`Role`, `Instigator`, …) | Use `SquadRole`, `InstigatorName`. MSVC C4458 is an error here too. |
| `unreal.log()` in `-run=pythonscript` commandlets does not reach stdout | Editor scripts write their result to `Saved/Logs/*.txt` (see `add_level_objects_to_movement_test.py`). |
| Editing a Blueprint's inherited component via Python CDO | Use `set_editor_property` on the component template; `set_relative_transform` is NOT persisted. |
| Git LFS for `.uasset/.umap` (no `lockable`) | `lockable` made maps read-only; keep it off. |
| The user re-laid `L_MovementTest` in the editor (whole layout rotated 180° and moved to Floor (-800, 1130); PlayerStart (-180, -1490)) — user decision 2026-09-29: keep it | Smokes write points in the original design coordinates (map script, Floor at the origin, yaw 0) and map them with `SmokeUtils::LevelPoint` / `LayoutTransform` (the "Floor" actor's location + yaw); `PlaceSquadAtTestStart` puts the squad at the design origin facing design +X. Never hard-code world coordinates in a smoke. |
| A saved `RecastNavMesh-Default` that is rotated / not tile-aligned stays empty at runtime ("Recreating dtNavMesh instance … not aligned with tile size", then nothing is built) | The map ships without a RecastNavMesh actor; it is created and built at load (RuntimeGeneration=Dynamic). A commandlet that loads and saves the map re-creates an EMPTY one that also stays empty at runtime: editor scripts must destroy `RecastNavMesh` actors before saving (see add_level_objects_to_movement_test.py). If smokes suddenly cannot move the squad ("leader on navmesh=0"), check this first. |
| Unity builds merge .cpp files (and adaptive unity compiles the files changed in git ALONE: a branch builds, its merge into main fails - twice on 2026-10-19: `AddDoubleSided`, `Margin`) | **Rule: every file-local name of a .cpp (anonymous namespace, `static`, file-scope `constexpr` / `const`, `TAutoConsoleVariable` / `FAutoConsoleCommand` variables, structs / enums / aliases defined in a .cpp, `DEFINE_LOG_CATEGORY_STATIC`, test classes) is unique within its module** - prefix it with the file's topic (`Minimap…`, `Loot…`, `ParseLockSteps`); two anonymous namespaces in one blob are ONE namespace, and a `using namespace X;` (even inside a function) makes X's names collide with the global / anonymous ones. A `#define` in a .cpp gets its `#undef` at the end (`LOCTEXT_NAMESPACE`). A helper two files need goes into a shared header (`…Internal.h`, `inline`). Check: `python Scripts/Tools/find_unity_clashes.py` (token-level scan of all modules' .cpp + project headers, ~6 s, exit 1 on a clash; `--self-test`, `--dump <file>`); `build.ps1` runs it before every build and prints a yellow `WARNING (unity clash)` per hit. Proof builds: `build.ps1 -FullUnity` (UBT `-DisableAdaptiveUnity`: what main sees) and `build.ps1 -NoUnity` (`-DisableUnity`: every file includes what it uses). Names like `FItemInfo` can also clash with engine types. |
| Default canvas / Slate fonts have no emoji | HUD / menu strip them (`ACodexTacticsHUD::StripUnsupportedGlyphs`); texts stay verbatim Godot with emoji in code. |
| CommonUI applies a default "Menu" input config to any activated screen unless `bEnableDefaultInputConfig=False` (DefaultGame.ini) — it would block the game's keys after the pause menu closed | Keep it False; a screen that wants an input mode implements "Get Desired Input Config" in its WBP. Screens are pooled by their stack: reset per-show state in `NativeOnActivated` / the push's init function, not the constructor. |
| Bash heredocs with long / complex Python sometimes break in this harness | Write the Python to the scratchpad with the file tool and run `python <file>`. |
| Smokes run on a fixed 60 fps game step (`smoke_parallel.ps1`, 2026-10-15) | Wait on CONDITIONS with generous caps, never on a fixed number of seconds for something async (path requests, nav rebuilds, a reload, a shimmy); thresholds per frame depend on the step (TurnBasedAimSmoke runs at 240). Freezing an enemy with `CustomTimeDilation = 0` does NOT stop its `TickBehavior` (DeltaTime 0, `AttackTimer` starts at 0: it still strikes when in reach) - also `SetActorTickEnabled(false)`; parking enemies only under the floor is not enough (panic, nearest-enemy and cone queries are 2D) - use `SmokeUtils::ParkEnemyFarAway`. |
| `AOperativeCharacter` is ONE class in ONE header but its members are defined in 16 .cpp files (`Private/Characters/OperativeCharacter<Cluster>.cpp`, cleanup day 2026-10-14) | Put new code in the file of its cluster (map: `docs/port/REFACTOR_OPERATIVE_2026-10.md` §3); a file-local helper two of those files need goes into `Private/Characters/OperativeCharacterInternal.h` (`namespace OperativeCharacterInternal`, `inline`), never into two anonymous namespaces (unity builds merge them). Each file includes only what it uses, so a new call may need a new `#include` there. BP-editable UPROPERTYs stay on the character. |
| `ACodexTacticsPlayerController` is ONE class in ONE header but its members are defined in 10 .cpp files (`Private/Core/CodexTacticsPlayerController<Area>.cpp`: main = input setup / PlayerTick / shared queries, Selection, Orders (`HandleWorldHit`), Stance, Items, Time, Menus, Camera, Cover; cleanup 2026-10-15; + Map = the minimap keys / clicks, 2026-10-18) | Put a new key / click handler in the file of its input area (map: `docs/port/REFACTOR_CONTROLLER_2026-10.md` §3); `ControllerCommands::Report` and the `OrderLock::CVarRealTimeOrders` CVar live in `Private/Core/CodexTacticsPlayerControllerInternal.h` (inline / extern) - never copy a helper into two units (unity builds merge them). Every unit keeps `LOCTEXT_NAMESPACE "CodexTacticsPlayerController"` and ends with `#undef LOCTEXT_NAMESPACE` (test `CodexTactics.Core.ControllerUnits.SourceLayout`). |
| `UPlaytestBotSubsystem` exists only in development builds (`CODEX_WITH_PLAYTEST_BOT` = not Test / Shipping) and only in Game / PIE worlds (`DoesSupportWorldType`, cleanup 2026-10-16) | `GetSubsystem<UPlaytestBotSubsystem>()` is null in editor / preview worlds and in a shipped game: check it. In Test / Shipping `-CodexBot`, `CodexTactics.Bot` and the `Codex.Bot.*` console variables do not exist (the tunables fall back to their defaults). |
| Dev console commands (smokes, probes, shots) live in the module `CodexTacticsDev` (`Source/CodexTacticsDev/Private/Debug/`, cleanup 2026-10-16), not in the runtime module | A new smoke goes there (`#include "Debug/SmokeUtils.h"` still works); it links against `CodexTactics`, so every runtime symbol it calls must be exported (`CODEXTACTICS_API` on the class / free function) and it cannot include the runtime module's `Private/` headers (e.g. `OperativeCharacterInternal.h`) - move what it needs to `Public/`. A new smoke no longer relinks the runtime DLL. `test.ps1 -CheckMap` scans this folder. |

- **Mesh on the capsule (rev 2026-10-19, user bug: the body ~1 m beside its selection ring, also while walking):** the skeletal mesh's
  XY / yaw relative to the capsule may differ from the Blueprint's (captured at BeginPlay: `MeshBaseXY` / `MeshBaseYaw`) only by the
  tracked cover offsets (`CoverEntryAppliedOffset`, `CoverWallPushAppliedLocal`, `CoverEntryAppliedYaw`); `EnforceMeshBaseOffset` puts
  anything else back every frame (Warning log). Root cause: the cover wall push was a scalar re-applied along the CURRENT facing - a
  turn / a teleport (load) / another wall while it was on left up to ~1.2 m on the mesh for good. It is a tracked actor-local vector
  now. Never move the mesh relative to the capsule without tracking it (smokes: `GetMeshBaseOffsetCm`, `ResetBodyOffsets`).
- **Holding a montage on its last frame:** clear `bEnableAutoBlendOut` on the running instance (`GetActiveInstanceForMontage(Montage)->bEnableAutoBlendOut = false`); the instance copies the montage's flag when it starts, so changing the montage after `PlaySlotAnimationAsDynamicMontage` has no effect.
- **Blend spaces made by script** (`UOperativeAnimGraphLibrary::FillDirectionalBlendSpace`) need `ValidateSampleData` + `ResampleData`; `PostEditChange()` alone leaves them empty and the player outputs the reference pose (T-pose height) with no error.

- **Two agents, one checkout:** set `$env:CODEX_AGENT` (claude / gemini); every build / test / smoke / verify_all takes `Saved/agent.lock` and waits for the other agent (`Scripts/agent_lock.ps1 -Status` shows the holder). Roles and file ownership: `docs/port/TANDEM.md`.
