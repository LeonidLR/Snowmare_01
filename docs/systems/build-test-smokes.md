### Verification tiers (2026-10-07; impact map `Scripts/test_map.json`)

`Scripts/test_map.json` maps changed paths (globs) -> unit-test filters + smokes (every smoke of `verify_all` is registered and mapped;
`test.ps1 -CheckMap` fails if a new `Debug/*Smoke*Command.cpp` is not). Add a rule / registry entry whenever you add a smoke or a system.

| Tier | When | Command |
|---|---|---|
| edit | after each change | `build.ps1`, then `test.ps1 -Changed -Quick` (one unit run with the combined filter + the 1-2 key smokes per rule, in parallel) |
| pre-commit | before the commit | `test.ps1 -Changed` (all mapped smokes) + `test.ps1` (all unit tests); `typesafe_triage.py --audit-diff --agent claude` |
| nightly / milestone | editor closed, big merges | `verify_all.ps1` (build + all tests + all smokes in parallel; `-Serial` for the old one-by-one run) |

- `test.ps1 -Changed [-Quick] [-Base <ref>] [-DryRun] [-SkipUnit|-SkipSmokes] [-Jobs N] [-Serial]`: files = `git diff --name-only <Base>` + untracked. `-DryRun` prints the plan only. `-Smart` = `-Changed` (the map decides; `-Jev` adds Jev's include-based unit filter as a hint).
- `smoke_parallel.ps1 -Commands a,b,c|all [-Jobs N] [-Serial]`: each smoke is its own UnrealEditor-Cmd with its own log `Saved/Logs/Smoke-<Name>.log`; the build lock is taken once for the batch. Smokes touching shared files (`SaveLoadSmoke`, `PauseMenuSmoke` -> `Saved/SmokeSaves`; `EventBusSmoke` -> `Saved/SaveGames`) are `exclusive` in the map and run alone after the batch; a parallel failure is re-run alone once (`PASS*` = passed only on the re-run, i.e. suspect flakiness). `knownFail` smokes (now `CombatMoveSmoke`) are shown as KNOWN-FAIL without failing the run. Default jobs = min(4, cores/4). The run ends with a "needed a re-run" line: PASS* smokes split into known flaky (`test_map.json` `knownFlaky`, name -> reason; empty since 2026-10-15) and NEW flaky ones; the result JSON lists them in `rerunPassed`.
- **Fixed game step (cleanup day 2026-10-15):** `smoke_parallel.ps1` starts every smoke with `-UseFixedTimeStep -FPS=60 -FixedSeed` (`test_map.json` `smokeDefaults`): each frame advances the game by exactly 1/60 s whatever the CPU load, so a smoke sees the same frames alone, with `-Jobs 3` or while the editor compiles shaders (load only stretches the wall time), and an unthrottled machine runs it several times faster than real time (CornerHoldSmoke 230 s -> ~60 s). 60 fps because the smokes' step tickers (0.05 / 0.1 / 0.25 s with `State.Time += step`) then land on whole frames: their counters equal the game time (30 fps drifted 25 %). Per-smoke `smokeOptions`: `realTime: true` (wall clock), `fixedStepFps` (TurnBasedAimSmoke 240: per-frame jitter metrics), `timeout` (CornerHoldSmoke 600). `-RealTime` runs the whole batch on the wall clock (old behaviour, for comparison). `smoke.ps1` still runs on the wall clock: add `-Extra "-UseFixedTimeStep -FPS=60 -FixedSeed"` to reproduce a batch result.
- Unmapped `Source/` paths fall back to the core smokes (`fallback` in the map); docs / scripts / `.claude` need nothing.
- Measured 2026-10-07 (16 cores, 4 jobs): `verify_all -SkipBuild` = 268 unit tests in 46 s + 91 smokes in 24.4 min wall (sum of checks 81.5 min; ~3.3x); serial smokes average ~54 s each (~82 min for all). Same per-smoke verdicts serial and parallel.
- The host re-checks only the build + one key smoke when the agent already ran the mapped set (`test.ps1 -Changed`) on the same tree.
