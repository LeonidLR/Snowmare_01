## 3. Tester feedback and telemetry plan

### 3.1 What already exists (reuse)

- `URunTelemetrySubsystem` (`Telemetry/`): **always on in every game world** (off only with `-NoTelemetry`), writes one JSON line per run (victory at PostCombat, defeat at GameOver) to `Saved/Telemetry/raw_runs/runs.jsonl`: per-operative stats, shots/damage per weapon per wave, deployable damage/kills, cold counters, remaining supplies, `TesterProfile` ("HUMAN" for players). This is exactly the data needed per tester run; it only fires at run *end*, so a tester who quits mid-way leaves no record (gap, see below).
- `FSpatialTelemetryRecorder` (`Bot/`): 10 Hz frames + events (SHOT, GRENADE_THROWN, ENEMY_DEATH, COVER_ENTER/LEAVE, CHOKE_CONGESTION) -> `Saved/Telemetry/spatial_runs/run_<session>.json`, consumed by the Wave Editor replay player. **Only started by the bot today.** Files reach 30-58 MB for long runs: for testers use 2 Hz, or only record player-triggered sessions and cap at ~5 MB.
- Jev digest: `python Scripts/Tools/typesafe_triage.py --telemetry <path>` compresses 100+ runs into a 3-line balance patch; use that instead of reading raw `runs.jsonl` (CLAUDE.md rule). `Scripts/Tools/jev_digest.py` for smoke/test output.
- Save slots are plain JSON: a tester's save is itself a repro artifact (map, flow phase, wave, squad state, enemies).

### 3.3 Short tester questionnaire (5 minutes, Google Form or in `README_TESTERS.md`)

1. Hardware: GPU, CPU, RAM, resolution (auto-filled from `session_start` where possible).
2. Did you finish the tutorial? How long did it take? Where did you stop? (list of beats)
3. Rate 1-5: clarity of controls, clarity of goals, difficulty, fun, performance.
4. Which mechanic was the hardest to understand? (pick: real-time orders, tactical pause, Space-hold turn-based, cover, deployables, cold/heat, inventory/transfer, combat modes)
5. Did you freeze to death? When? Did the cold feel fair? (a free-text "moment you almost quit")
6. Any bug: what happened, what you expected (the F8 reports complement this).
7. "Would you play the next level?" and "What would you tell a friend about the game in one sentence?"

### 3.4 How reports come back

Demo #1 (small tester group, see Q1): tester sends the `Report_*.zip` by email/Discord/Google Drive link to a private channel. QA reads `report.json` files (one per ticket) and the sessions telemetry, runs `typesafe_triage.py --telemetry sessions.jsonl` for the digest, then triages into a short bug list (Severity S1-S4, tags: Blocker/Crash/Gameplay/Balance/UX/Perf/Art). Later (demo #2+): an upload endpoint, Steam/itch builds with built-in crash upload.

1. Build id on the main menu matches the tag and release notes; `BuildInfo.json` present.
2. Cold boot to title in < 60 s; no shader-compile hitching longer than 2 s in the first minute (first run is slower: say so).
3. Main menu: NEW GAME, CONTINUE (greyed with a reason on a fresh install), LOAD, OPTIONS (graphics preset, resolution, volume work and persist), CREDITS, QUIT with confirm.
4. NEW GAME -> intro briefing (all lines, English, no `[EN missing]`), Space advances, Esc skip.
5. Walk every tutorial beat in order at normal pace; every prompt appears once, text matches the action, key names are right (F8 feedback, F5 quicksave, etc.), nothing blocks progress when the player does steps in a different order or skips one.
6. Mechanics, each once: select/group-select, move/sprint/crouch/prone, cover, line of fire, Ctrl+click shot, barrel/mine/turret/barricade deployment, grenade, loot crate, transfer (drag & drop), inventory, heat pack/campfire/flare (if included), tactical pause (tap), plan, turn-based (Space hold), knockdown get-up.
7. Cold: the first 5 minutes never kill a competent player; warning cues appear before frostbite.
8. Combat: one wave on CASUAL-ish defaults is winnable by a first-time player without reading docs; death -> mission failed screen -> restart works; victory panel -> next steps -> end-of-demo screen with the questionnaire link and "send report" instructions.
9. Save in exploration (F5 / pause menu), quit to menu, CONTINUE, F9; autosave appears after a wave; save refused during combat with the message.
10. F8 feedback: report created, screenshot not black, log tail and save present, folder opens from the menu; `SendReport.bat` makes a zip < 25 MB.
11. Alt+Tab, window/fullscreen switch, resolution change, 2nd monitor, ultrawide 21:9 and 1080p/1440p/4K UI scaling (HUD canvas text clipping), pause with Esc while in dialogue.
12. Performance on the weakest available machine: biggest fight stays >= 30 fps (A6 numbers), no memory growth after a 20-minute session.
13. Quit paths: menu Quit, Alt+F4 mid-fight (session_end recorded on next start), kill process (crash folder created).
14. Clean machine test (no UE installed, fresh Windows user, no admin rights): launches with no missing DLL/redistributable errors (VC++ runtime and DirectX prerequisites; the package should include `UE_PrereqSetup_x64.exe` or a README line).
15. README_TESTERS.md in the zip: min/recommended spec (DX12 SM6 GPU), controls cheat sheet, known issues (B7, B9, B11 as applicable), how to send the report, whom to contact, no-redistribution clause.
