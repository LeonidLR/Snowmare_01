# Formation work - contracts between the parts (coordinator: «Маршрутизатор моделей», user decision 2026-10-25)

Design source: `docs/design/FORMATION_SECTORS.md` (+ `formation-sectors.html`). This file fixes the DATA the parts exchange, so
the TypeScript simulator (Training Ground), the C++ rules and the Unreal map generator can be built in parallel and meet.
Units: centimetres, degrees, seconds. Yaw: strictly UE - X forward, Y right, yaw = atan2(dy, dx) in degrees, growing from +X
towards +Y (clockwise seen from above); "clock" sectors are relative to the leader's heading: clock c -> yaw = heading + 30*c
(12 = heading, 3 = right = heading + 90, 9 = left = heading - 90). Coordinator decision 2026-10-25 (the first version had the
sign mirrored). Config: `Content/Data/FormationLab/formation_config.json`, schema `codex.formation_config/1`,
`params: { "<key>": { value, min, max, unit, doc } }`, scalars only; angles relative to the leader's heading (or the wall's
outward normal for `wall.*`), positive = right. Owned by the cloud session (Training Ground); the tuner changes only `value`.

## 1. Layout JSON - `Content/Data/FormationLab/<name>.json` (one file feeds the simulator AND the Unreal map generator)
```json
{
  "schema": "codex.formation_layout/1",
  "name": "formation_lab_01",
  "bounds": { "min": [-6000, -6000], "max": [6000, 6000] },
  "ground_z": 0,
  "spawn": { "pos": [0, 0], "yaw": 0 },
  "walls": [ { "id": "W1", "a": [x, y], "b": [x, y], "height": 300, "thickness": 40 } ],
  "zones": [ { "id": "Z1", "kind": "open|corridor|wall_run|gap_run|corner|wall_end", "poly": [[x, y], ...] } ],
  "routes": [ { "id": "R1", "pace": "walk|run", "points": [[x, y], ...],
               "expect": [ { "zone": "Z1", "formation": "diamond|wedge|column|line|echelon_left|echelon_right|wall|hedgehog|blizzard" } ] } ]
}
```
- Walls are straight segments; a gap = two segments. Corners = two segments sharing an end point.
- Zones are labels for the checks (what the terrain classifier SHOULD say), not geometry.
- Routes are the leader's click path; the bot walks the squad along each route.
- Optional `"props": [ { "id": "HEAT_A", "kind": "heat_source", "pos": [x, y] } ]` - set dressing for the map builder only
  (heat_source -> an unlit ACampfireActor for the hedgehog); the rules and the checks ignore it (cloud session, stage 5).
- The big lab `formation_lab_01.json` is generated by `npm run lab:gen` (Tools/TrainingGround/src/movement/cli/genLab.ts) -
  edit the generator, not the JSON; `Scripts/Editor/build_formation_lab.py` builds `/Game/Maps/L_FormationLab` from it
  (TargetPoints `<route id>_<n>`, tags FormationLabRoute + the route id).

## 2. Pure rules (same names in TS and C++; TS first, C++ ports them; golden vectors prove equality)
- `FormationShapeRules::Slots(formation, memberCount, leaderPos, leaderYaw, config) -> slots[]` (pos + role K/P/L/Z).
- `FormationSectorRules::LookYaw(role, formation, mode(walk|run|halt|wall), memberCount, timeInPatrol, leaderYaw, config) -> yaw`
  (patrol scans: P 12->3, L 9->12 counter-phase, dwell; Z walks backwards looking at 6; with memberCount 2 the partner is
  role Z behind the right shoulder and SWEEPS 3 -> 6 -> 9 (`pair.scan_period / scan_from / scan_to`), user decision in
  FORMATION_SECTORS.md; coordinator 2026-10-25). In mode `wall` leaderYaw is the wall's outward normal.
- **v1.1 (2026-10-25, coordinator; user Q1 = A / Q2 = A; Q3 classifier fix)** - supersedes the v1 lines below where they differ:
  - `FormationSectorRules::LookYaw(role, formation, mode, memberCount, timeInPatrol, leaderYaw, passageWidth, config)`:
    `passageWidth` (cm, null = not between two walls); a `column` with passageWidth < `column.narrow_width` looks P
    +`column.narrow_fwd_deg` (15), L -`column.narrow_back_deg` (-165), Z 180, K 0; else the herringbone (+-`column.side_deg`).
  - New `FormationTerrainRules::PassageWidth(walls, leaderPos, leaderYaw, config) -> cm | null` (left + right side clearance
    when both sides are blocked, else null) - the runtime passes it to LookYaw every tick.
  - `Classify` / `PassageWidth` side probes ignore wall segments within `classify.side_ignore_perp_deg` (30) of perpendicular to
    the heading (`isAcrossHeading`); the ahead / at_wall rays are evaluated first.
  - `echelon.sector_4` default 150 (was 125). Config v1.1: 51 keys (+ classify.side_ignore_perp_deg, column.narrow_width,
    column.narrow_fwd_deg, column.narrow_back_deg). Golden: + `formation_PassageWidth.json`; LookYaw cases carry passageWidth.
- `FormationTerrainRules::Classify(layout walls, leaderPos, leaderYaw, previousClass, timeInClass, config) -> class`
  (open / wall_left / wall_right / corridor / at_wall) with hysteresis (like ColumnHoldTime) -> formation choice.
- `FormationWallRules::Layout(wall segment, clickedSlot, memberCount, roomLeft, roomRight) -> slots[] + look yaws`
  (L 8, K 6 away from the wall, P 4; the 4th at the roomier end, his neighbour turns to the centre).
- Config defaults in one place: `Content/Data/FormationLab/formation_config.json` (spacing, pace 0.8, hysteresis s, scan
  periods); both sides read it.

## 3. Golden vectors - `Tools/TrainingGround/golden/formation_<rule>.json`
```json
{ "schema": "codex.formation_golden/1", "rule": "Slots", "tolerance": { "cm": 0.5, "deg": 0.5 },
  "cases": [ { "in": { ... }, "out": { ... } } ] }
```
Exported by the simulator (`npm run golden`); C++ parity tests `CodexTactics.Formation.Parity.<Rule>` read them from
`FPaths::ProjectDir()/Tools/TrainingGround/golden/` (skip with a warning while the file does not exist yet).

### 3.1 Field names the C++ parity harness reads (`Source/CodexTacticsTests/Private/Formation/FormationParityTest.cpp`)
Top level: `schema` = `codex.formation_golden/1`, `rule` = the file's rule name, `tolerance.cm` / `tolerance.deg` (default 0.5 / 0.5),
`config_values` = flat `{ "<config key>": number }` snapshot the vectors were computed with (the C++ config is built FROM it over the
struct defaults, never from the current `formation_config.json`; an unknown key is a warning), `cases` = non-empty array of
`{ in, out }`. Every case is checked, none skipped; an unreadable case is an error. Input names are camelCase (snake_case aliases
`member_count`, `leader_pos`, ... are accepted too). Vectors are `[x, y]` cm; yaws UE degrees compared as angles (|normalize(a - b)| <=
tolerance.deg, 180 == -180); positions by distance <= tolerance.cm. Enum strings: formation `diamond | wedge | column | line |
echelon_left | echelon_right | wall | hedgehog | blizzard`, role `K | P | L | Z`, mode `walk | run | halt | wall`, class
`open | wall_left | wall_right | corridor | at_wall`. Walls `{ a: [x, y], b: [x, y], thickness? }` (thickness missing = 0).

| File / test | `in` | `out` (compared) |
|---|---|---|
| `formation_Slots.json` / `Parity.Slots` | `formation`, `memberCount`, `leaderPos`, `leaderYaw` | `slots: [{ role, pos }]` - same count, same role ORDER (index 0 = the leader; `wall` -> `[]`), pos |
| `formation_LookYaw.json` / `Parity.LookYaw` | `role`, `formation`, `mode`, `memberCount`, `timeInPatrol`, `leaderYaw` (mode / formation `wall`: the wall's outward normal) | `yaw` |
| `formation_Classify.json` / `Parity.Classify` | `walls[]`, `leaderPos`, `leaderYaw`, `previousClass` (string or `null` = no history), `timeInClass` | `class` (after the hysteresis) |
| `formation_FormationFor.json` / `Parity.FormationFor` | `class`, `memberCount` | `formation` |
| `formation_WallLayout.json` / `Parity.WallLayout` | `wall`, `clickedSlot`, `memberCount`, `roomLeft`, `roomRight` | `slots: [{ role, pos, yaw }]` - same count / role order, pos, yaw |

C++ entry points: `FormationShapeRules::Slots`, `FormationSectorRules::LookYaw(role, formation, mode, memberCount, timeInPatrol,
leaderYaw, config)`, `FormationTerrainRules::Classify(walls, leaderPos, leaderYaw, TOptional previousClass, timeInClass, config)` /
`FormationFor(class, memberCount)`, `FormationWallRules::Layout(wall, clickedSlot, memberCount, roomLeft, roomRight, config)`;
config `FFormationConfig` + `FormationTuning` (`Source/CodexTactics/Public/Formation/`). First run 2026-10-25 against ead0faf:
Slots 288, LookYaw 3888, Classify 264, FormationFor 15, WallLayout 108 cases, 0 mismatched.

## 4. Movement bot report - `Saved/TrainingGround/movement/report.md` (<= 30 lines; the ONLY thing a coding agent reads)
Header: layout, routes, runs, seed. Then one line per check with pass / fail counts and the worst case (route id, time):
1. wall stare: nobody looks into a wall closer than 200 cm (facing within 45 deg of the wall normal, towards it);
2. rear cover: with 4 members the 5-7 o'clock sector is watched >= 90 % of patrol time; with 3 the gap is reported, not failed;
3. flicker: formation changes per 100 m of route (target <= 1 outside expected changes);
4. expected formation per zone (routes[].expect) matched;
5. slots: no slot inside a wall / off the walkable area; spacing within config;
6. pace: the rear man keeps <= 150 cm behind his slot at patrol pace.
Raw runs: `Saved/TrainingGround/movement/runs.jsonl` (never read by agents). Advice (optional): Jev (`TYPESAFE_API_KEY`) or the
Claude API (`ANTHROPIC_API_KEY`) turns runs.jsonl into <= 10 lines of tuning advice appended to the report; without a key the
report says "no model advice".

## 6. Bot training on the user's API tokens (user request 2026-10-25: "use the API tokens as much as possible, train the bot through the cloud APIs")
The tuner loop - `Tools/TrainingGround` department "movement", `npm run train -- --budget-usd <N> --rounds <N>`:
1. simulate a series (deterministic TS, 0 tokens): every route x N seeds with the current `formation_config.json`;
2. distil the series to a compact JSON summary (check stats, worst cases, current parameters) - never raw runs;
3. ask the Claude API (`ANTHROPIC_API_KEY`, model `claude-opus-5-5` for proposals, `claude-sonnet-5-5` for summaries; Jev
   `TYPESAFE_API_KEY` for typed pass/fail judgments when available) for the next parameter set as strict JSON within allowed
   ranges (the ranges live next to the defaults in formation_config.json);
4. keep the best set (score = weighted checks of section 4), stop on budget, on no improvement for K rounds, or on all checks green;
5. write `Saved/TrainingGround/movement/train_report.md` (<= 30 lines: rounds, spend, best score, the winning parameters as a
   diff) and `train_best_config.json`. A coding agent reads only train_report.md; the winning config goes into main only after
   the coordinator's review.
Budget: a hard cap per run (`--budget-usd`, default 5), the spend counted from the API's token usage and logged per call; the
key is read from the environment / HKCU and never printed. The same loop pattern later serves the waves bot and the
level-design bot (Training Ground departments).
Where it runs: the user's PC (the key lives there). The cloud session builds the loop with a mock client (no key, no network)
and a `--dry-run`; the coordinator's local agent wires the real client and runs the first training.

## 7. Integration requirements for the runtime (stage 6; found by the simulator, coordinator 2026-10-25)
- **Follower speed with velocity lead.** Today `SquadFormation::ComputeFollowerSpeed` slows a follower proportionally inside
  `SlowRadius` (250 cm) even while his slot moves, so at walking pace every follower trails ~2 m behind his slot and the rear
  man never closes a gap (the sectors / pace in the game then differ from the simulator). The runtime must move a follower
  with the slot's own velocity (feed-forward) plus a proportional correction towards the slot: `v = v_slot * jitter +
  dir * min(top * catchup_mult, d * FOLLOW_GAIN)`, `FOLLOW_GAIN = 2 / s`, capped by `top * move.catchup_mult` and, walking
  backwards (> 120 deg off his facing), by `pace.walk_speed * move.backward_mult`; stop only when within 25 cm AND the slot is
  still. Reference: `Tools/TrainingGround/src/movement/sim.ts` `stepTowards`.
- **Walking into the wall layout:** a member walking to his wall slot faces his travel direction and turns to the layout yaw
  only within 100 cm of the slot (else he looks into the passage walls on the way; sim `WALL_TURN_DIST`).
- **The wall layout only on arrival.** A wall straight ahead (`at_wall`) while the leader still walks is a corner to turn: keep
  the previous formation; switch to `FormationWallRules::Layout` when the leader stops at the wall (or on a cover order).
